# Work Log

個人用の作業記録アプリ。案件ごとに1レコード、進捗と作業ログを残していく。

**このアプリの目的は案件管理ではなく、痕跡を残すこと。** 記録ツールの死に方はいつも同じで、
綺麗に作って2週間で止まる。差が出るのは「1件記録するのに何秒かかるか」だけ——なので
作業ログの常駐1行入力欄が、この画面でいちばん重要な部品。

## 使い方

`app.html` をブラウザで開くだけ。ビルド不要、サーバー不要。
初回起動時はサンプル案件が5件入っているので、削除するか中身を書き換えて自分の案件にする。

## 画面

| 場所 | 役割 |
|---|---|
| 左上・気泡エリア | 1つの気泡＝1案件。**サイズ**＝現在の投入強度（進捗に沿った正規曲線／小→大→小）、**濃淡**＝完了度（進むほど濃く）。絞り込み時も気泡は動かず、該当するものだけが光る |
| 右上・詳細 | 選択中の案件。進捗ノード（1–10、クリックで前後）、作業ログ、リンク。未選択時は「最後に更新した案件」を表示 |
| 下・一覧 | 全案件。最終更新が常に最上段。DETAIL から案件ごとのメモ＋ログ全文を開く |
| 左下・サイドバー | ステータス／案件タイプ／クライアントで絞り込み。気泡と一覧に同時に効く |

進捗を10まで進めると完了フロー——気泡が一度膨らんでから上へ抜けていく。
**このアプリで儀式的な演出をするのはここだけ**、他は静かに保つ。

## 設定（歯車アイコン）

- **言語** — English ／ 日本語 ／ 繁體中文
- **タグ管理** — 案件タイプとクライアントの一覧。事前登録も、使わなくなったタグの削除もできる
- **About** — バージョン、制作者、保存先

## データ

現在は `localStorage`（キー: `work-tracker-v1`）に JSON 1件。一人で数十件の想定なので DB は不要。

> ⚠️ ブラウザのサイトデータを消すと記録も消える。デスクトップアプリ化の際に
> 実ファイル（JSON）へ移行する予定——それが MCP 連携の前提でもある（下記）。

## 今後

- **Tauri でデスクトップアプリ化** — Rust ツールチェーンと Tauri CLI は導入済み
- **保存先を実ファイルへ** — `localStorage` はブラウザのサンドボックス内にあり、外部プロセスから読めない
- **MCP サーバー** — 上記のファイル化が済めば、Claude から作業記録を読み書きできるようになる

## デザイン

Ameba のスタイルリファレンス（`DESIGN.md`）をトークンごと適用している。ピル形の角丸だけは
意図的にリファレンスから外している（リファレンスは 8px 上限）。

## ファイル

| ファイル | 中身 |
|---|---|
| `app.html` | アプリ本体（単一ファイル、依存なし） |
| `SPEC.md` | 仕様と決定の記録。**却下した案とその理由も含む**——ないと同じ議論を繰り返す |
| `DESIGN.md` | 適用中のスタイルリファレンス（Ameba） |
| `wireframe.html` | 最初のワイヤーフレーム（番号付き仕様説明つき） |
| `wireframe-ameba.html` | ワイヤーフレームにスタイルを当てた検証用 |
